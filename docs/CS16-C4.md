# Original C4 models and handling

The C4 uses the approved GameBanana viewmodel, including the original hands,
textures, skeleton, idle, draw, keypad and lowering animations. The original
`p_c4` appears in players' hands and while bots plant. The small held model is
preloaded with each avatar so the first plant does not wait for its GLB to load. Planted bombs use `w_c4`;
dropped bombs use `w_backpack`. Blender 5.2.1 LTS exported all four models at
0.025 metres per GoldSrc unit. The viewmodel has 808 triangles and 37 bones;
the held, planted and backpack models have 128, 116 and 44 triangles. Maximum
sampled bone-matrix error is below 0.000002.

C4 is assigned to a Terrorist for free each round. Select it with **4**, hold
left mouse inside a bomb site to plant, and release to cancel. **Shift+4** drops
it; **Shift+2** also drops it while selected. A living Terrorist can retrieve it
once it lands, including during freeze time.

- Manual drops and carrier deaths throw the backpack at 400 units/s (10 m/s),
  from 10 units ahead of the standing body center. The forward vector uses the
  source body pitch, minus one third of view pitch; looking down throws slightly
  upward. Gravity and floor/wall clipping use the shared weapon-box physics.
- Pickup requires a settled box touching the standing player bounds: 16-unit
  horizontal box extents and 16 units above the box origin. CTs and dead players
  cannot collect it. There is no extra delay for the former owner. Physics keeps
  running through the round result; the new round removes the dropped model.
  Unlike discarded firearms, the backpack has no five-minute item expiry.
- Deploy blocks planting for 0.75 seconds. C4 movement speed is 6.25 m/s,
  independent of the previous weapon; walking applies the existing 0.52 factor.
- Planting requires three uninterrupted seconds. Keypad animation starts locally
  and does not replay on server acknowledgment. The source lowering clip begins
  after 2.25 seconds, at its original playback speed, and is interrupted by
  weapon retirement when planting completes.
- Keypad clicks come from the seven original MDL sound events. Switching to the
  lowering animation cancels remaining keypad events, as in the original.
- Releasing during a plant enforces a one-second retry delay. Losing the ground
  or leaving the site enforces 1.5 seconds. An early cancel returns to idle; a
  cancel after lowering begins draws the C4 again. Holstering cancels the action
  and deploys the requested owned weapon, including the previously held gun.
- Plant completion selects the highest-weight available weapon. Defused bombs
  disappear. These decisions, deployment delays and invalid actions are checked
  on the authoritative server.
- The existing fuse remains 45 seconds. Defusing takes ten seconds, or five with
  the $200 kit. [Kits recovered from dead CTs](CS16-DEFUSE-KITS.md) provide the same benefit. Terrorist use near the bomb does not freeze movement. Existing three-frag objective awards and round decisions remain.
- Blast damage uses the source 500 damage / 1750-unit linear falloff: 43.75 metres
  at this weapon calibration, without wall occlusion. Damage stays fractional
  until armor processing. The blast source rises 45.6 units from the floor, then
  one further unit for the radius-damage calculation.
- The original LED sprite flashes for 0.1 seconds every two seconds. Explosion
  fireballs and subsequent smoke use original sprite artwork. Source `Explode2`
  writes a negative scale to a byte; its wrapped value is preserved (151 / 10).

## Sources and reproduction

Game rules follow the compatibility path in
[ReGameDLL CS, revision b0889847](https://github.com/rehlds/ReGameDLL_CS/tree/b0889847fe6d03898be88acc9e366660efb40ab5):
`wpn_shared/wpn_c4.cpp`, `player.cpp`, `weapons.cpp`, `ggrenade.cpp`, `basemonster.cpp` and
`combat.cpp`. Source-specific fix/addition branches are not treated as stock
CS 1.6 behavior. Body/view pitch mapping and toss clipping follow pinned ReHLDS
[`sv_user.cpp`](https://github.com/rehlds/ReHLDS/blob/6266cd23faee4a6e9cf3974f9605b2cadd86f0a4/rehlds/engine/sv_user.cpp)
and [`sv_phys.cpp`](https://github.com/rehlds/ReHLDS/blob/6266cd23faee4a6e9cf3974f9605b2cadd86f0a4/rehlds/engine/sv_phys.cpp).

The [approved viewmodel pack](https://gamebanana.com/mods/227246) supplies
`fixed_v_c4.mdl`. Other original files come from the pinned CS-Server archive.
[Source hashes](../asset-sources/cs16-weapons/c4/sources.json) and
[Blender reports](../asset-sources/cs16-weapons/c4/reports.json) retain provenance.
Existing weapon converters reproduce these files: `import_weapon` for the
viewmodel, `export_world('c4', ...)` for the held model, and `export_drop` for
`c4` and `backpack`. The GLBs contain only each weapon and embedded textures.

Run `npm run validate`. It includes timing/cancellation tests and validates C4
source hashes, exported geometry, bones, animation endpoints and media files.
Use `node validate/prepare-c4.mjs /tmp/cs16-c4-review` for an isolated browser
fixture, then install its dependencies and run `npm start -- --web --port 8011`.
For the defuse check, create another fresh fixture with the extra argument
`defuse`. It places only the current stationary Terrorist bomb carrier inside A; normal
bot bomb logic plants the bomb.

Open the official Bevy browser preview against that realm using an isolated,
muted headless browser with WebGPU and loopback permission. Run
`node validate/c4.mjs <CDP-websocket> <evidence-directory> <browser-session>`;
for the defuse fixture use `validate/c4-defuse.mjs` with the same arguments.
These scripts exercise real pointer/key input and read the scene through Bevy
console CRDT snapshots. Tiny diagnostic TextShapes exist only in the fixtures.
See [browser evidence](../validate/game/c4/README.md). The separate
[toss regression](../validate/game/c4-toss/README.md) covers flight, freeze-time
pickup, body-pitch gun drops, a real fatal fall and next-round cleanup.

## Remaining differences

The carrier's back-mounted backpack remains pending. Bots hold the original C4
while planting but use Decentraland avatars
and animations. The progress UI and C4 text hints have not received the same
source-layout comparison as the buy menu and scoreboard.

The source 1-unit/s arming movement is represented by freezing SDK locomotion.
The scene implements source-based acceleration on desktop Bevy; exact GoldSrc
crouching, hull dimensions and collision behavior remain unfinished.
The use range is 64 units, but its hull-center/eye mapping still uses the scene's
avatar dimensions. Bomb-site volumes follow the existing Dust2 map calibration. Tosses use the
original BSP point hull and fixed 120 Hz substeps; this is not exact engine
cadence parity. Teleporting above the BSP sky can place an item inside solid
space even when Bevy shows open air; the browser fixture stays below that boundary.
Crouched drop origins and exact animated body/death orientation remain open.

Sprite alpha blending approximates GoldSrc additive rendering. Dynamic light,
scorch decals, sparks and the original explosion screen shake are not reproduced.
Bevy's light/texture response and hand attachment also differ from GoldSrc.
Muted browser checks establish clip scheduling and asset loading; they are not
an audible timing or spatial attenuation comparison with the original client.
