# Original CS player bodies

`arctic.mdl` (Terrorist) and `urban.mdl` (Counter-Terrorist) are the original Valve GoldSrc IDST v10 models from the same pinned mirror used for the approved world weapons. Exact URLs, sizes and SHA-256 hashes are in [sources.json](sources.json). These remain Valve assets; the mirror does not grant a separate asset license.

The live official Blender MCP imported and validated both models in Blender 5.2.1. `convert_player.py` reads original rigid bone weights, palette textures and animation channels through `player_model.py`. Reproduce with the players and `../cs16-weapons` directories on Python's path, then call `convert_player.import_player(source_mdl, output_directory)` in Blender. It creates a separate scene and restores the previous active scene.

Geometry is 721 triangles for Arctic and 790 for Urban, at 0.025 metres per original unit. The origin is at the feet (36 source units below the MDL origin), with a -90° Blender Z rotation. Stock Bevy rotates each glTF root 180° around Y; with the SDK coordinate conversion this puts the body forward along SDK +Z. New bots use scale 1 and their authoritative navigation feet/yaw; no avatar scale or 90° death rotation is inherited. Idle glTF bounds are recorded in the conversion reports; heights are about 1.53 m, width under 0.7 m and depth under 0.96 m. Navigation keeps their origins inside Dust2; their limbs can extend beyond the movement hull, as in CS.

The exporter retains the default bodygroup without a C4 backpack. Urban's collar includes two opposite faces sharing source vertices but using different UVs. Splitting vertices by source vertex/normal/UV preserves both, preventing Blender's mesh validation from discarding a face. Skeleton bind matrices use Blender's stored rest pose; maximum checked matrix error against decoded source poses is 0.00000716 (limit 0.0001).

`prepare_player.py` keeps 48 unique source clips plus restart aliases, separates torso and leg channels using the original [StudioModelRenderer gait mask](https://github.com/ValveSoftware/halflife/blob/master/cl_dll/StudioModelRenderer.cpp), and exports the original 20 active body hitboxes and their bone tracks. Nine-way sequences currently select the neutral blend, index 4. Pose files compact constant tracks and round to seven decimals. The runtime composes the selected leg and torso bones, interpolates their source positions/quaternions and tests rays in each oriented box. The inactive shield box is excluded.

Gun animation families and death activities follow [ReGameDLL player animation selection](https://github.com/rehlds/ReGameDLL_CS/blob/master/regamedll/dlls/player.cpp) and each weapon's `DefaultDeploy` animation extension. Bots use original aiming/firing/reload poses, independent idle/walk/run legs, and full-body deaths. Held world weapons bind through stock Bevy's `GltfNode` to the original hand path, with SDK quaternion (-0.5, 0.5, -0.5, 0.5) compensating the world-weapon export and glTF bone basis. The existing SDK compatibility package supplies the protocol; no renderer patch is used.

Remaining differences: aim pitch/yaw blend poses, gait-facing twist, crouching/jumping selection, C4 backpack, flinch animation overlays, directional corpse throws and human character replacement are not implemented here. Original body animations do not change the server's weapon damage, recoil, cadence, pricing, rounds or match format.
